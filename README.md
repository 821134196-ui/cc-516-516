# 🌿 云枝农场 · 采摘券系统

按作物和园区发售采摘券，覆盖 **采摘日历 → 购券预约 → 入口核销 → 离园称重结算 → 退款/补扣** 全流程。
纯 Python 标准库 + SQLite，无外部依赖，一条本地命令启动。

## 启动

```bash
./run.sh                 # 首次自动播种演示数据（含次日雨天停园样例）并启动
# 或：PORT=8000 ./run.sh
```

打开浏览器：

| 端 | 地址 | 说明 |
|---|---|---|
| 游客端 | http://127.0.0.1:8000/ | 优先展示可预约日期与剩余名额、购券、改期/转赠/退票 |
| 现场端 | http://127.0.0.1:8000/gate | 大号券码核销、大号电子秤读数、离园结算、补扣款 |
| 管理端 | http://127.0.0.1:8000/admin | 园区图（可采/停采边界）、当天停采、雨天全园停园、受影响预约退改、流水 |

重建演示数据：`python3 -m app.seed --reset`
运行测试：`python3 -m unittest discover -s tests`（22 个用例）

## 演示数据与推荐剧本

数据库已内置：今天待核销券、在园中券、已离园已补款券、**网关故障挂账待补扣券**、
明天（雨天全园停园）受影响券 2 张、今天暖阳橘园「果实未熟」受影响券。

1. **管理端**：看明天 🌧 雨天停园 → 受影响预约逐券「退款 / 改期」；今天橘园显示果实未熟停采。
2. **游客端**：日历首屏即看到明天停园与各分区剩余名额；雨天券卡片上出现退改提示。
3. **现场端**：核销「今天待核销」券 → 用同券码在「东门」重放被拒；模拟控制台**断开电子秤**后称重被拒（禁止人工估重）→ 恢复后置数结算；支付网关下线时超额自动挂账，恢复后在「待补扣」里补扣款。

## 关键业务规则

- **券重放**：`checkins (ticket_id)` 唯一约束 + 票状态机 + 进程锁三重保证，一张券只能核销一次，不可能在两个入口重复入园。
- **核销与改期互斥**：核销后状态为 `used`，改期立即拒绝；并发场景下有进程锁串行化，两者不可能同时成功（有测试）。
- **重量计费**：超额 = 秤读数 −（基础重量 + 儿童免费重量 × 儿童数），按券种 元/kg 计费。
- **检票员不能改称重**：称重接口只接收券码，重量**只能**来自电子秤适配器；称重记录一次性写入、重复结算返回 `already_weighed`，系统不存在人工写重量的入口。
- **电子秤断连**：结算中止并明确报错，券保持在园，恢复后再称；不允许手工录入。
- **离园后补扣款**：支付网关故障时超额费用挂 `pending` 账，游客先离园；网关恢复后 `/api/settle` 补扣，幂等不多扣。
- **临时停采/雨天/果实未熟**：按「分区 × 日期」落库；受影响的**未入园**预约在管理端列出，提供原路退款或改到其他可采日期；名额随退款释放。
- **券转赠**：旧券作废保留流水，签发新券码并迁移预约；旧码再核销提示已转赠。

## 结构

```
app/
  db.py         SQLite 建表/连接（WAL、外键、busy_timeout）
  adapters.py   模拟电子秤（可断连）与模拟支付（可下线→挂账→补扣）
  services.py   领域服务：日历/购券/核销/改期/转赠/称重/退款/补扣/停采
  server.py     标准库 ThreadingHTTPServer，JSON API + 静态页面
  seed.py       演示数据（含次日雨天停园样例）
static/         三端 HTML/JS/CSS 与本地 SVG 演示图片（白/果园绿/金黄）
tests/          unittest：券重放、重量计费、停采改期、并发入园等 22 项
farm.db         SQLite（运行时生成，已 gitignore）
```
